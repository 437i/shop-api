# frontend/products-management Specification

## Purpose

Раздел административной панели для управления каталогом: создание товара с выбором поставщика, удаление с подтверждением и уменьшение остатка с обработкой ошибок и локализацией EN/RU.

## Requirements

### Requirement: Форма создания товара

Система MUST предоставлять форму создания товара с полями Name, Category, Price, Available Stock и Supplier и MUST отправлять данные на `POST /api/v1/products` с Bearer-авторизацией.

#### Scenario: Открытие формы создания

- **WHEN** пользователь находится на странице `/products` и активирует действие создания товара
- **THEN** система отображает форму с полями Name, Category, Price, Available Stock, Supplier

#### Scenario: Успешное создание товара

- **WHEN** пользователь отправляет форму с валидными значениями
- **THEN** система отправляет POST-запрос на `/api/v1/products` с телом `{"name": "<name>", "category": {"name": "<category>"}, "price": "<price>", "available_stock": <целое число>, "supplier_id": "<supplier id>"}`
- **THEN** поле `price` содержит значение в виде строки без преобразования
- **THEN** при ответе 201 система закрывает форму
- **THEN** система инвалидирует кеш списка товаров
- **THEN** созданный товар отображается в обновлённом списке

#### Scenario: Блокировка повторной отправки

- **WHEN** запрос создания выполняется
- **THEN** кнопка отправки становится disabled и отображает текст выполнения
- **THEN** повторная отправка формы невозможна до завершения запроса

### Requirement: Клиентская валидация формы создания товара

Система MUST проверять форму до отправки: обязательность всех полей, максимум 255 символов для Name и Category, формат Price по правилу backend `^[1-9]\d{0,9}(\.\d{1,2})?$` и целое положительное значение Available Stock.

#### Scenario: Пустые обязательные поля

- **WHEN** пользователь отправляет форму с пустым обязательным полем
- **THEN** система отображает сообщение валидации
- **THEN** запрос на `/api/v1/products` не отправляется

#### Scenario: Превышение длины поля

- **WHEN** значение Name или Category превышает 255 символов
- **THEN** система отображает сообщение валидации
- **THEN** запрос на `/api/v1/products` не отправляется

#### Scenario: Некорректная цена

- **WHEN** цена не соответствует шаблону `^[1-9]\d{0,9}(\.\d{1,2})?$` (например, `0.5`, `007`, `10.123`, `abc`)
- **THEN** система отображает сообщение валидации о некорректной цене
- **THEN** запрос на `/api/v1/products` не отправляется

#### Scenario: Корректная цена

- **WHEN** цена соответствует шаблону `^[1-9]\d{0,9}(\.\d{1,2})?$` (например, `10`, `999.99`)
- **THEN** система считает значение валидным и не блокирует отправку

#### Scenario: Некорректный остаток

- **WHEN** остаток не является целым положительным числом (например, `0`, `-1`, `1.5`, `abc`)
- **THEN** система отображает сообщение валидации о некорректном остатке
- **THEN** запрос на `/api/v1/products` не отправляется

#### Scenario: Поставщик не выбран

- **WHEN** пользователь отправляет форму, не выбрав поставщика
- **THEN** система отображает сообщение валидации
- **THEN** запрос на `/api/v1/products` не отправляется

### Requirement: Выбор поставщика в форме создания товара

Система MUST загружать поставщиков через `GET /api/v1/suppliers` с Bearer-авторизацией и MUST предоставлять выбор поставщика по имени с отправкой его `id` в поле `supplier_id`.

#### Scenario: Опции поставщиков

- **WHEN** GET-запрос на `/api/v1/suppliers` возвращает 200 с массивом поставщиков и форма создания товара открыта
- **THEN** система отображает для каждого поставщика опцию с отображаемой подписью `name`
- **THEN** значением опции является поле `id` поставщика

#### Scenario: Загрузка поставщиков

- **WHEN** список поставщиков загружается
- **THEN** выбор поставщика и отправка формы недоступны до завершения загрузки
- **THEN** система не отправляет форму с пустым `supplier_id`

#### Scenario: Пустой список поставщиков

- **WHEN** GET-запрос на `/api/v1/suppliers` возвращает 200 с пустым массивом
- **THEN** система отображает сообщение о необходимости сначала создать поставщика
- **THEN** отправка формы недоступна

#### Scenario: Ошибка загрузки поставщиков

- **WHEN** GET-запрос на `/api/v1/suppliers` завершается ошибкой или сетевой ошибкой
- **THEN** система отображает сообщение об ошибке загрузки поставщиков
- **THEN** отправка формы недоступна

### Requirement: Ошибки мутаций отображаются и сохраняют ввод

Система MUST отображать понятное сообщение при неуспешном ответе мутации (400, 404, 409, 500, 503 или сетевая ошибка) и MUST сохранять введённые данные в открытой форме.

#### Scenario: Ошибка 400 с сообщением

- **WHEN** мутация завершается ответом 400 с полем `message` в ErrorResponse (например, `empty name`, `invalid price`, `empty category`, `invalid request body`)
- **THEN** система отображает сообщение из поля `message`

#### Scenario: Ошибка 400 без сообщения

- **WHEN** мутация завершается ответом 400 без поля `message`
- **THEN** система отображает "Invalid request"

#### Scenario: Ошибка 404 при создании товара

- **WHEN** запрос создания завершается ответом 404 с полем `message` (например, `supplier not found`)
- **THEN** система отображает сообщение из поля `message`
- **THEN** если поле `message` отсутствует, система отображает локализованное сообщение о том, что поставщик не найден

#### Scenario: Ошибка 404 при удалении и уменьшении остатка

- **WHEN** запрос удаления или уменьшения остатка завершается ответом 404 с полем `message` (например, `product not found`)
- **THEN** система отображает сообщение из поля `message`
- **THEN** если поле `message` отсутствует, система отображает локализованное сообщение о том, что товар не найден

#### Scenario: Ошибка 409 при уменьшении остатка

- **WHEN** запрос уменьшения остатка завершается ответом 409 с полем `message` (например, `insufficient stock`)
- **THEN** система отображает сообщение из поля `message`
- **THEN** если поле `message` отсутствует, система отображает локализованное сообщение о недостаточном остатке

#### Scenario: Ошибки сервера и сеть

- **WHEN** мутация завершается ответом 500 или 503 без поля `message`
- **THEN** система отображает "Server error. Please try again later."
- **WHEN** запрос не возвращает ответ (timeout, network error)
- **THEN** система отображает "Network error. Please try again."

#### Scenario: Ввод сохраняется при ошибке отправки формы

- **WHEN** отправка формы завершается ошибкой
- **THEN** форма остаётся открытой
- **THEN** введённые пользователем значения сохранены

#### Scenario: 401 завершает сессию

- **WHEN** мутация завершается ответом 401
- **THEN** система удаляет токен, очищает кеш и перенаправляет на `/auth/login` в соответствии с существующим глобальным поведением

### Requirement: Удаление товара с подтверждением

Система MUST предоставлять удаление товара из строки списка только после явного подтверждения и MUST отправлять `DELETE /api/v1/products/{id}` с Bearer-авторизацией лишь при подтверждении.

#### Scenario: Подтверждение показывает товар

- **WHEN** пользователь активирует удаление в строке товара
- **THEN** система отображает диалог подтверждения с именем этого товара
- **THEN** доступное имя действия содержит имя товара

#### Scenario: Отмена удаления

- **WHEN** пользователь отменяет подтверждение
- **THEN** запрос на удаление не отправляется
- **THEN** список товаров не изменяется

#### Scenario: Успешное удаление

- **WHEN** пользователь подтверждает удаление
- **THEN** система отправляет DELETE-запрос на `/api/v1/products/{id}`
- **THEN** при ответе 204 система закрывает диалог подтверждения
- **THEN** система инвалидирует кеш списка товаров
- **THEN** удалённый товар отсутствует в обновлённом списке

#### Scenario: Ошибка удаления

- **WHEN** запрос удаления завершается ответом 404 с полем `message`
- **THEN** система отображает это сообщение в диалоге подтверждения
- **THEN** список товаров не меняется

#### Scenario: Блокировка повторного удаления

- **WHEN** запрос удаления выполняется
- **THEN** элементы управления подтверждения становятся disabled
- **THEN** повторная отправка невозможна до завершения запроса

### Requirement: Уменьшение остатка из строки списка

Система MUST позволять уменьшать остаток товара из строки списка, MUST предзаполнять диалог текущим `available_stock` товара и MUST отправлять `PATCH /api/v1/products/{id}/stock` с телом ровно `{"amount": <целое число>}`.

#### Scenario: Открытие формы уменьшения остатка

- **WHEN** пользователь активирует уменьшение остатка в строке товара
- **THEN** система отображает форму с именем товара и текущим значением `available_stock` из загруженного списка
- **THEN** система не выполняет дополнительный запрос за данными товара

#### Scenario: Успешное уменьшение остатка

- **WHEN** пользователь отправляет форму с валидным значением
- **THEN** система отправляет PATCH-запрос на `/api/v1/products/{id}/stock` с телом ровно `{"amount": <значение>}`
- **THEN** при ответе 204 система закрывает форму
- **THEN** система инвалидирует кеш списка товаров
- **THEN** обновлённый список отображает уменьшенный `available_stock`

#### Scenario: Предупреждение о нулевом остатке

- **WHEN** введённая сумма уменьшения равна текущему `available_stock` товара
- **THEN** система отображает локализованное предупреждение: товар исчезнет из списка после уменьшения до нуля, так как API не поддерживает пополнение остатка
- **THEN** система не блокирует отправку формы

#### Scenario: Товар исчезает из списка после уменьшения до нуля

- **WHEN** уменьшение остатка до 0 завершилось ответом 204
- **THEN** система инвалидирует кеш списка товаров
- **THEN** обновлённый список, полученный от `GET /api/v1/products`, не содержит этот товар (контракт возвращает только товары с `available_stock > 0`)

#### Scenario: Ошибка 409 при устаревших данных

- **WHEN** PATCH-запрос завершается ответом 409 (например, остаток на сервере меньше введённой суммы)
- **THEN** система отображает сообщение об ошибке в форме
- **THEN** форма остаётся открытой, список товаров не меняется

#### Scenario: Отмена уменьшения остатка

- **WHEN** пользователь отменяет форму уменьшения остатка
- **THEN** PATCH-запрос не отправляется
- **THEN** данные списка не изменяются

### Requirement: Клиентская валидация суммы уменьшения остатка

Система MUST проверять сумму уменьшения до отправки: обязательность, целое положительное число, не превышающее текущий `available_stock` товара.

#### Scenario: Пустая сумма

- **WHEN** пользователь отправляет форму с пустой суммой
- **THEN** система отображает сообщение валидации
- **THEN** PATCH-запрос не отправляется

#### Scenario: Сумма не является целым положительным числом

- **WHEN** сумма равна `0`, отрицательна или не является целым числом (например, `1.5`, `abc`)
- **THEN** система отображает сообщение валидации
- **THEN** PATCH-запрос не отправляется

#### Scenario: Сумма превышает текущий остаток

- **WHEN** сумма больше текущего `available_stock` товара
- **THEN** система отображает сообщение валидации
- **THEN** PATCH-запрос не отправляется

#### Scenario: Сумма равна текущему остатку

- **WHEN** сумма равна текущему `available_stock` товара
- **THEN** система считает значение валидным и не блокирует отправку

### Requirement: Инвалидация кеша списка товаров

Система MUST инвалидировать кеш списка `["products"]` только после успешного завершения мутации (201 для создания, 204 для удаления и уменьшения остатка) и MUST NOT инвалидировать его при неуспешных запросах.

#### Scenario: Успешная мутация обновляет кеш

- **WHEN** мутация создания, удаления или уменьшения остатка завершилась успешно
- **THEN** система помечает кеш списка товаров устаревшим
- **THEN** список отображает актуальные данные с сервера

#### Scenario: Неуспешная мутация не обновляет кеш

- **WHEN** мутация завершилась ошибкой 400, 404, 409, 500, 503 или сетевой ошибкой
- **THEN** система не инвалидирует кеш списка товаров
- **THEN** отображаемые данные списка не изменяются

#### Scenario: 401 очищает кеш глобально

- **WHEN** мутация завершилась ответом 401
- **THEN** кеш очищается существующим глобальным обработчиком 401, а сессия завершается

### Requirement: Локализация раздела товаров

Система MUST отображать все тексты операций раздела товаров (кнопки, подписи полей, опции, диалоги подтверждения, предупреждения, сообщения валидации и ошибок) на выбранном языке: английском или русском.

#### Scenario: Английский язык

- **WHEN** выбранный язык — английский
- **THEN** действия, подписи формы создания, формы уменьшения остатка, диалога удаления, предупреждения и сообщения валидации отображаются на английском

#### Scenario: Русский язык

- **WHEN** выбранный язык — русский
- **THEN** действия, подписи формы создания, формы уменьшения остатка, диалога удаления, предупреждения и сообщения валидации отображаются на русском
