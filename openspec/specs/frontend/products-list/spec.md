# frontend/products-list Specification

## Purpose

Отображает каталог товаров, доступных в наличии, через `GET /api/v1/products` с обработкой состояний загрузки, ошибок и пустого списка и локализацией EN/RU.

## Requirements

### Requirement: Страница отправляет запрос на список товаров

Система MUST отправлять GET-запрос на `/api/v1/products` с Bearer-авторизацией при загрузке страницы `/products`.

#### Scenario: Запрос с Bearer токеном
- **WHEN** пользователь открывает страницу `/products`
- **THEN** система отправляет GET-запрос на `/api/v1/products` с заголовком `Authorization: Bearer <token>`, где `<token>` — значение из localStorage под ключом `auth_token`

### Requirement: Состояние загрузки отображает skeleton loader

Система MUST отображать skeleton loader, пока запрос списка товаров не завершён.

#### Scenario: Загрузка данных
- **WHEN** пользователь открывает страницу `/products` и запрос к API находится в процессе выполнения
- **THEN** система отображает skeleton loader вместо таблицы
- **THEN** skeleton содержит 5 строк с заглушками колонок

### Requirement: Успешный ответ с данными отображает таблицу

Система MUST отображать таблицу товаров при успешном ответе 200 с непустым массивом, используя только поля `internal_product.ListResponse`.

#### Scenario: Успешный ответ с товарами
- **WHEN** GET-запрос на `/api/v1/products` возвращает 200 с массивом товаров
- **THEN** система отображает таблицу с колонками: Name, Category, Price, Available Stock
- **THEN** каждая строка таблицы соответствует одному элементу массива `internal_product.ListResponse[]`
- **THEN** колонка "Name" содержит значение поля `name`
- **THEN** колонка "Category" содержит значение поля `category.name`
- **THEN** колонка "Price" содержит значение поля `price` без изменений
- **THEN** колонка "Available Stock" содержит значение поля `available_stock`
- **THEN** каждая строка содержит меню действий с пунктами уменьшения остатка и удаления

### Requirement: Пустой список отображает empty state для товаров в наличии

Система MUST отображать empty state при успешном ответе 200 с пустым массивом и MUST описывать его как отсутствие товаров в наличии, поскольку контракт возвращает только товары с `available_stock > 0`.

#### Scenario: Пустой список товаров
- **WHEN** GET-запрос на `/api/v1/products` возвращает 200 с пустым массивом `[]`
- **THEN** система отображает сообщение "No products in stock"
- **THEN** система отображает иллюстрацию или иконку пустого состояния
- **THEN** таблица не отображается

### Requirement: Ошибки списка отображаются на странице

Система MUST отображать сообщение об ошибке при неуспешных ответах 500 и 503 и при сетевой ошибке; статус 400 для этого запроса контрактом не предусмотрен, так как у запроса нет параметров.

#### Scenario: Internal Server Error (500) с сообщением
- **WHEN** GET-запрос на `/api/v1/products` возвращает 500 с полем `message` ErrorResponse
- **THEN** система отображает Alert с сообщением из поля `message`
- **THEN** таблица не отображается

#### Scenario: Internal Server Error (500) без сообщения
- **WHEN** GET-запрос на `/api/v1/products` возвращает 500 без поля `message`
- **THEN** система отображает Alert с сообщением "Server error. Please try again later."
- **THEN** таблица не отображается

#### Scenario: Service Unavailable (503)
- **WHEN** GET-запрос на `/api/v1/products` возвращает 503 (auth middleware, тело с полем `error` без `message`)
- **THEN** система отображает Alert с сообщением "Server error. Please try again later."
- **THEN** таблица не отображается

#### Scenario: Сетевая ошибка без ответа
- **WHEN** GET-запрос на `/api/v1/products` не возвращает ответ (timeout, network error)
- **THEN** система отображает Alert с сообщением "Network error. Please try again."
- **THEN** таблица не отображается

### Requirement: Ошибка 401 завершает сессию

Система MUST обрабатывать ответ 401 от `GET /api/v1/products` как истёкший или невалидный токен и завершить сессию.

#### Scenario: Unauthorized response
- **WHEN** GET-запрос на `/api/v1/products` возвращает 401
- **THEN** система удаляет токен из localStorage
- **THEN** система очищает кеш TanStack Query
- **THEN** система перенаправляет пользователя на `/auth/login`

### Requirement: Кеширование и автоматическое обновление списка

Система MUST использовать TanStack Query для кеширования списка товаров. При возврате на вкладку система MUST автоматически повторять запрос к `/api/v1/products`, только если кешированные данные устарели (прошло более staleTime = 5 минут); данные в пределах staleTime новый запрос из-за возврата фокуса не вызывают.

#### Scenario: Повторное открытие страницы в течение staleTime
- **WHEN** пользователь открывает страницу `/products`, затем переходит на другую страницу, затем возвращается в течение 5 минут
- **THEN** система отображает данные из кеша TanStack Query без нового запроса к API
- **THEN** skeleton loader не отображается

#### Scenario: Возврат на вкладку с устаревшими данными
- **WHEN** пользователь возвращается на вкладку, где открыта страница `/products`, и кешированные данные старше staleTime (5 минут)
- **THEN** TanStack Query автоматически повторяет запрос на `/api/v1/products` для получения актуальных данных
- **THEN** во время фонового обновления данные из кеша остаются отображёнными
- **THEN** skeleton loader не отображается, пока данные из кеша доступны

#### Scenario: Возврат на вкладку в пределах staleTime
- **WHEN** пользователь возвращается на вкладку, где открыта страница `/products`, и кешированные данные не старше staleTime (5 минут)
- **THEN** новый запрос на `/api/v1/products` не отправляется
- **THEN** отображаются данные из кеша TanStack Query

### Requirement: Поддержка локализации таблицы

Система MUST отображать заголовки таблицы и сообщения страницы `/products` на выбранном языке.

#### Scenario: Английский язык
- **WHEN** пользователь открывает страницу `/products` и выбранный язык — английский
- **THEN** заголовки колонок отображаются на английском: "Name", "Category", "Price", "Available Stock"
- **THEN** сообщения об ошибках и empty state отображаются на английском

#### Scenario: Русский язык
- **WHEN** пользователь открывает страницу `/products` и выбранный язык — русский
- **THEN** заголовки колонок отображаются на русском: "Название", "Категория", "Цена", "Доступный остаток"
- **THEN** сообщения об ошибках и empty state отображаются на русском

### Requirement: Ошибка загрузки списка товаров предлагает повторную загрузку

Система MUST отображать в состоянии ошибки загрузки списка товаров действие «Повторить», повторяющее запрос `GET /api/v1/products`.

#### Scenario: Запрос списка товаров завершился ошибкой
- **WHEN** GET-запрос на `/api/v1/products` завершился ошибкой 500, 503 или сетевой ошибкой
- **THEN** система отображает Alert с сообщением об ошибке
- **THEN** система отображает в этом Alert действие «Повторить»

#### Scenario: Повторная загрузка списка товаров
- **WHEN** пользователь активирует действие «Повторить»
- **THEN** система повторно отправляет GET-запрос на `/api/v1/products`

#### Scenario: Повторная загрузка успешна
- **WHEN** повторный GET-запрос на `/api/v1/products` вернул 200 с массивом товаров
- **THEN** система отображает таблицу товаров
- **THEN** действие «Повторить» не отображается

### Requirement: Переход к карточке товара из строки списка

Система MUST предоставлять в меню действий каждой строки списка товаров действие перехода к карточке товара, открывающее страницу `/products/{id}`, где `{id}` — идентификатор товара этой строки.

#### Scenario: Действие в меню строки

- **WHEN** пользователь открывает меню действий строки товара
- **THEN** система отображает действие перехода к карточке товара
- **THEN** активация действия открывает страницу `/products/{id}` этого товара

#### Scenario: Действие доступно в каждой строке

- **WHEN** список товаров содержит несколько товаров
- **THEN** действие перехода к карточке доступно в меню действий каждой строки
- **THEN** колонки таблицы, меню уменьшения остатка, управления фотографией и удаления не изменяются
