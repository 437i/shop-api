# Proposal

## Why

Раздел «Поставщики» показывает только строку списка: имя, телефон и адрес. Данных строки достаточно, чтобы обзорно просмотреть справочник, но поставщик не имеет собственного экрана, в отличие от товара: теперь карточка товара (`/products/:id`) поддерживает просмотр фонда данных товара, а у поставщика аналогичного взгляда нет. Раздел поставщиков растёт: телефон и адрес используются для связи при заказах и приемке, и пользователю нужен быстрый доступ к «всё о поставщике» без редактирования и с постоянным URL, куда можно вернуться.

## What Changes

- Новая защищённая страница `/suppliers/:id` — карточка поставщика: получает данные через `GET /api/v1/suppliers/{id}` и отображает все поля `internal_supplier.Response` (name, phone_number, адрес: country/city/street).
- Переход из списка: в меню действий каждой строки `/suppliers` появляется первым пунктом действие карточки поставщика, открывающее страницу `/suppliers/{id}`; возврат к списку — действие на самой странице.
- Состояния страницы: skeleton загрузки, карточка при 200, отсутствие поставщика при 404 (сообщение и возврат к списку), ошибки 400/500/503 и сетевая ошибка с действием «Повторить», завершение сессии при 401 через существующий глобальный обработчик.
- Кеширование данных карточки в TanStack Query по правилам панели (staleTime 5 минут, автообновление по фокусу при устаревании), отдельный ключ `["supplier", id]`, актуализация кеша после мутаций поставщика из списка (изменение адреса, удаление).
- Ключи локализации EN/RU для всех текстов карточки.
- **Без изменений Go API, Java-сервиса и схемы БД.** Контракт `GET /api/v1/suppliers/{id}` (router `api/internal/server/router.go:63`, swagger 200 `internal_supplier.Response`) уже объявлен и достаточен; фронтенд его сейчас так же не использует, как до недавнего времени не использовал `GET /api/v1/products/{id}`.
- **Не является BREAKING**: существующие страницы не меняют поведение, в `/suppliers` добавляется только пункт меню.

Не входит в scope:

- Редактирование имени и телефона поставщика на карточке — операции `PATCH` этих полей в контракте нет (`PATCH /suppliers/{id}` не существует); панель не добавляет действия, которые контракт не поддерживает. Фотография и даты в ответе тоже отсутствуют — блоков для них на карточке не создаётся.
- Изменение адреса на карточке — существующий диалог «Edit address» остаётся в меню строки списка; карточка остаётся местом просмотра.
- Карточка клиента и справочник адресов — отдельные темы.
- Живой e2e-сценарий для карточки (`frontend/e2e-live/`) — существующая пятисценарная живая процедура остаётся без изменений.

## Capabilities

### New Capabilities

- `frontend/supplier-details`: страница карточки поставщика — загрузка данных через `GET /api/v1/suppliers/{id}`, отображение полей `internal_supplier.Response` (имя, телефон, адрес), состояния загрузки, отсутствия поставщика, ошибок и завершения сессии, возврат к списку, локализация.

### Modified Capabilities

- `frontend/suppliers-management`: в меню действий строки поставщика добавляется действие открывания карточки `/suppliers/:id`, и существующие мутации строки актуализируют кеш карточки. Таблица и её состояния не меняются.

## Impact

**Используемые API-эндпоинты** (контракт не меняется, перечислены как затрагиваемая поверхность):
- `GET /api/v1/suppliers/{id}` — 200 `internal_supplier.Response`; 400 `invalid supplier id` (некорректный UUID в пути); 401 unauthorized; 404 `supplier not found`; 500. Код 503 в swagger не задокументирован — это поведение auth middleware, общее для всех защищённых эндпоинтов панели (так же задокументировано в спецификациях `frontend/products-list` и `frontend/product-details`).
- `GET /api/v1/suppliers` — существующий список; создаёт поставщиков, карточки которых доступны по прямому URL.
- `PATCH /api/v1/suppliers/{id}/address`, `DELETE /api/v1/suppliers/{id}` — существующие мутации строки; их инвалидирующий эффект расширяется на кеш карточки (`["supplier"]`), сами запросы не меняются.

**Код фронтенда:**
- `frontend/src/app/router.tsx` — новый защищённый маршрут `/suppliers/:id`.
- `frontend/src/pages/suppliers/` — страница карточки `SupplierDetailsPage.tsx`, хук данных `useSupplierDetails.ts`, константа ключа кеша в `useSupplierMutations.ts`; пункт меню в `SuppliersListPage.tsx`.
- `frontend/src/shared/i18n/locales/en/common.json`, `frontend/src/shared/i18n/locales/ru/common.json` — ключи локализации.
- `frontend/src/test/`, `frontend/e2e/` — юнит- и браузерные тесты.

**Зависимости:** новых нет — используются уже подключённые React Router, TanStack Query, react-i18next и компоненты shadcn/ui. Паттерн карточки повторяет `frontend/product-details` (хук `useProductDetails`, страница `ProductDetailsPage`, e2e-мок в `helpers.ts`), применённый к поставщику.

**Не затрагивается:** Go API, Java auth service, схема БД, разделы клиентов и товаров, навигация sidebar, живой e2e-набор, локальные моки разработки (`mockAuthModule`), архив завершённых изменений.

**Незавершённые вопросы контракта и аутентификации:**
- Профиль пользователя из `internal_supplier.Response` не создаётся: это данные поставщика товара, а не сведения о пользователе; панель по-прежнему не запрашивает профиль и права (см. `frontend/admin-access-model`).
- `GET /api/v1/suppliers/{id}` допускает 400 (`invalid supplier id`), поэтому в отличие от списка поставщиков карточка обрабатывает 400 как ошибку загрузки с сообщением сервера.
- Токен не обновляется при открытии карточки, refresh-механизма в контракте нет: поведение завершения сессии при 401 остаётся тем же, что и у остальных защищённых запросов.
