# Spec Delta

## Purpose

Страница карточки поставщика в административной панели: отображает полные данные поставщика из `GET /api/v1/suppliers/{id}` — имя, телефон и адрес, — с состояниями загрузки, отсутствия поставщика, ошибок и завершения сессии, локализацией EN/RU и возвратом к списку поставщиков.

## ADDED Requirements

### Requirement: Карточка отправляет запрос данных поставщика

Система MUST отправлять GET-запрос на `/api/v1/suppliers/{id}` с Bearer-авторизацией при открытии страницы `/suppliers/:id`, где `{id}` — значение параметра маршрута.

#### Scenario: Запрос с Bearer токеном

- **WHEN** пользователь открывает страницу `/suppliers/:id`
- **THEN** система отправляет GET-запрос на `/api/v1/suppliers/{id}` с заголовком `Authorization: Bearer <token>`, где `<token>` — значение из localStorage под ключом `auth_token`

### Requirement: Состояние загрузки отображает skeleton

Система MUST отображать skeleton карточки, пока запрос данных поставщика не завершён.

#### Scenario: Загрузка данных карточки

- **WHEN** пользователь открывает страницу `/suppliers/:id` и запрос к API находится в процессе выполнения
- **THEN** система отображает skeleton вместо содержимого карточки

### Requirement: Карточка отображает данные поставщика

Система MUST при успешном ответе 200 отображать данные `internal_supplier.Response` и MUST использовать только поля этого контракта: имя, телефон и адрес (страну, город, улицу).

#### Scenario: Поля карточки отображены

- **WHEN** GET-запрос на `/api/v1/suppliers/{id}` возвращает 200 с телом `internal_supplier.Response`
- **THEN** система отображает имя `name`, телефон `phone_number`
- **THEN** система отображает блок адреса: `address.country`, `address.city`, `address.street`

### Requirement: Отсутствующий поставщик обрабатывается состоянием карточки

Система MUST при ответе 404 на `GET /api/v1/suppliers/{id}` отображать состояние отсутствия поставщика с локализованным сообщением и действием возврата к списку поставщиков.

#### Scenario: Поставщик не найден

- **WHEN** GET-запрос на `/api/v1/suppliers/{id}` возвращает 404
- **THEN** система отображает локализованное сообщение об отсутствии поставщика
- **THEN** система отображает действие возврата к списку поставщиков
- **THEN** содержимое карточки не отображается

### Requirement: Ошибки загрузки карточки отображаются с повтором

Система MUST при неуспешных ответах 400, 500, 503 и при сетевой ошибке запроса `GET /api/v1/suppliers/{id}` отображать сообщение об ошибке и действие «Повторить», повторяющее запрос.

#### Scenario: Ошибка с сообщением сервера

- **WHEN** GET-запрос на `/api/v1/suppliers/{id}` возвращает 400 или 500 с полем `message` ErrorResponse
- **THEN** система отображает Alert с сообщением из поля `message`
- **THEN** система отображает в этом Alert действие «Повторить»

#### Scenario: Ошибка без сообщения сервера

- **WHEN** GET-запрос на `/api/v1/suppliers/{id}` возвращает 500 без поля `message`, возвращает 503 независимо от тела ответа, либо запрос не возвращает ответ
- **THEN** система отображает Alert с локализованным сообщением об ошибке
- **THEN** действие «Повторить» отправляет повторный GET-запрос на `/api/v1/suppliers/{id}`

#### Scenario: Повторная загрузка успешна

- **WHEN** повторный GET-запрос на `/api/v1/suppliers/{id}` возвращает 200
- **THEN** система отображает карточку поставщика
- **THEN** действие «Повторить» не отображается

### Requirement: Ошибка 401 завершает сессию

Система MUST обрабатывать ответ 401 от `GET /api/v1/suppliers/{id}` как истёкший или невалидный токен через общее поведение завершения сессии панели.

#### Scenario: Unauthorized response

- **WHEN** GET-запрос на `/api/v1/suppliers/{id}` возвращает 401
- **THEN** система удаляет токен из localStorage
- **THEN** система очищает кеш TanStack Query и перенаправляет пользователя на `/auth/login`

### Requirement: Возврат к списку поставщиков

Система MUST предоставлять действие возврата к списку поставщиков на странице `/suppliers/:id`.

#### Scenario: Возврат из карточки

- **WHEN** пользователь активирует действие возврата на странице `/suppliers/:id`
- **THEN** система открывает страницу `/suppliers`

### Requirement: Данные карточки кешируются

Система MUST кешировать данные карточки в TanStack Query с глобальными правилами панели: повторное открытие карточки того же поставщика в пределах staleTime (5 минут) не отправляет новый запрос, при устаревании кеша происходит его обновление.

#### Scenario: Повторное открытие карточки в пределах staleTime

- **WHEN** пользователь повторно открывает карточку того же поставщика в течение 5 минут
- **THEN** новый GET-запрос на `/api/v1/suppliers/{id}` не отправляется
- **THEN** отображаются данные из кеша

#### Scenario: Повторное открытие карточки после staleTime

- **WHEN** пользователь повторно открывает карточку того же поставщика позже чем через 5 минут
- **THEN** система отправляет повторный GET-запрос на `/api/v1/suppliers/{id}`

### Requirement: Мутации поставщика из списка актуализируют карточку

Система MUST актуализировать кеш карточки после успешных мутаций этого поставщика, выполняемых из списка: после изменения адреса карточка при следующем открытии показывает актуальный адрес, после удаления поставщика — состояние отсутствия поставщика.

#### Scenario: Адрес изменён из списка

- **WHEN** пользователь изменил адрес поставщика из строки списка, затем открыл карточку этого поставщика
- **THEN** карточка отправляет GET-запрос на `/api/v1/suppliers/{id}` заново и отображает актуальный адрес

#### Scenario: Поставщик удалён из списка

- **WHEN** пользователь удалил поставщика из строки списка, затем открыл карточку этого поставщика по прямой ссылке
- **THEN** GET-запрос на `/api/v1/suppliers/{id}` возвращает 404 и карточка отображает состояние отсутствия поставщика

### Requirement: Локализация карточки

Система MUST отображать все тексты карточки (названия полей, действия, состояния, сообщения) на выбранном языке: английском или русском.

#### Scenario: Английский язык

- **WHEN** пользователь открывает карточку поставщика при выбранном английском языке
- **THEN** все тексты карточки отображаются на английском

#### Scenario: Русский язык

- **WHEN** пользователь открывает карточку поставщика при выбранном русском языке
- **THEN** все тексты карточки отображаются на русском

### Requirement: На карточке нет операций, не поддерживаемых контрактом

Система MUST отображать на карточке только просмотр данных и возврат к списку и MUST NOT отображать операции изменения имени, телефона или адреса, поскольку контракт `GET`-карточки их не предоставляет, а изменение адреса остаётся в меню строки списка.

#### Scenario: Состав действий карточки

- **WHEN** карточка поставщика открыта
- **THEN** на карточке доступно только действие возврата к списку
- **THEN** на карточке нет действий изменения имени, телефона или адреса
