# Spec Delta

## Purpose

Защищает административные маршруты от неавторизованного доступа и предоставляет навигацию с возможностью выхода.

## ADDED Requirements

### Requirement: Защищённые маршруты требуют токен

Система MUST проверять наличие токена в localStorage перед отображением защищённых маршрутов.

#### Scenario: Доступ без токена перенаправляет на вход
- **WHEN** пользователь пытается открыть защищённый маршрут `/clients` без токена в localStorage
- **THEN** система перенаправляет пользователя на `/auth/login`
- **THEN** защищённая страница не отображается

#### Scenario: Доступ с токеном отображает страницу
- **WHEN** пользователь открывает защищённый маршрут `/clients` и в localStorage присутствует токен под ключом `auth_token`
- **THEN** система отображает запрошенную страницу в административном layout

### Requirement: Ответ 401 завершает сессию

Система MUST обрабатывать ответ 401 от защищённых API endpoints, удалять токен и перенаправлять на страницу входа.

#### Scenario: Защищённый запрос возвращает 401
- **WHEN** пользователь находится на защищённой странице и выполняется запрос к API (например, `GET /api/v1/clients`)
- **THEN** при ответе 401 система удаляет токен из localStorage
- **THEN** система очищает кеш TanStack Query
- **THEN** система перенаправляет пользователя на `/auth/login`

#### Scenario: Ошибка входа не инициирует logout
- **WHEN** пользователь отправляет форму входа на `/api/v1/auth`
- **THEN** при неуспешном ответе (400, 502 или неожиданный 401) система отображает ошибку
- **THEN** система не удаляет существующий токен из localStorage (если он присутствовал)
- **THEN** система не перенаправляет на страницу входа

### Requirement: Выход удаляет токен и перенаправляет

Система MUST предоставлять функцию выхода, которая очищает сессию и возвращает на страницу входа.

#### Scenario: Пользователь нажимает кнопку выхода
- **WHEN** пользователь находится в административном layout и нажимает кнопку "Logout"
- **THEN** система удаляет токен из localStorage под ключом `auth_token`
- **THEN** система очищает кеш TanStack Query
- **THEN** система перенаправляет пользователя на `/auth/login`

### Requirement: Административный layout содержит навигацию

Система MUST отображать навигационное меню с доступными разделами административного интерфейса.

#### Scenario: Отображение навигационного меню
- **WHEN** пользователь находится на защищённой странице
- **THEN** система отображает sidebar с пунктами меню: "Clients", "Products", "Suppliers"
- **THEN** активный раздел визуально выделен
- **THEN** текущий активный раздел — "Clients"

#### Scenario: Неактивные разделы недоступны
- **WHEN** пользователь находится в административном layout
- **THEN** пункты меню "Products" и "Suppliers" отображаются как disabled
- **THEN** нажатие на disabled пункты не выполняет навигацию

### Requirement: Переключатель языка доступен в layout

Система MUST предоставлять переключатель языка интерфейса в административном layout.

#### Scenario: Переключение на русский язык
- **WHEN** пользователь находится в административном layout и выбранный язык — английский
- **THEN** система отображает переключатель языка с текущим значением "EN"
- **THEN** при нажатии на переключатель язык меняется на русский
- **THEN** все тексты интерфейса обновляются на русский язык
- **THEN** текущее значение переключателя — "RU"

#### Scenario: Переключение на английский язык
- **WHEN** пользователь находится в административном layout и выбранный язык — русский
- **THEN** при нажатии на переключатель язык меняется на английский
- **THEN** все тексты интерфейса обновляются на английский язык

### Requirement: Маршрут корня перенаправляет на clients

Система MUST перенаправлять пользователя с корневого маршрута `/` на `/clients`.

#### Scenario: Авторизованный пользователь открывает корень
- **WHEN** пользователь открывает `/` и в localStorage присутствует токен
- **THEN** система перенаправляет пользователя на `/clients`

#### Scenario: Неавторизованный пользователь открывает корень
- **WHEN** пользователь открывает `/` без токена в localStorage
- **THEN** система перенаправляет пользователя на `/clients`
- **THEN** ProtectedRoute проверяет отсутствие токена и перенаправляет на `/auth/login`

### Requirement: Несуществующие маршруты отображают 404

Система MUST отображать страницу 404 для несуществующих маршрутов.

#### Scenario: Доступ к несуществующему маршруту
- **WHEN** пользователь открывает несуществующий маршрут (например, `/nonexistent`)
- **THEN** система отображает страницу с текстом "404: Page Not Found"
- **THEN** страница содержит ссылку для возврата на главную страницу
