# Spec Delta

## Purpose

Страница карточки товара в административной панели: отображает полные данные товара из `GET /api/v1/products/{id}`, включая поставщика с телефоном и адресом, показывает фотографию товара и предоставляет управление ею через существующий диалог, с состояниями загрузки, отсутствия товара, ошибок и завершения сессии, локализацией EN/RU и возвратом к списку товаров.

## ADDED Requirements

### Requirement: Карточка отправляет запрос данных товара

Система MUST отправлять GET-запрос на `/api/v1/products/{id}` с Bearer-авторизацией при открытии страницы `/products/:id`, где `{id}` — значение параметра маршрута.

#### Scenario: Запрос с Bearer токеном

- **WHEN** пользователь открывает страницу `/products/:id`
- **THEN** система отправляет GET-запрос на `/api/v1/products/{id}` с заголовком `Authorization: Bearer <token>`, где `<token>` — значение из localStorage под ключом `auth_token`

### Requirement: Состояние загрузки отображает skeleton

Система MUST отображать skeleton карточки, пока запрос данных товара не завершён.

#### Scenario: Загрузка данных карточки

- **WHEN** пользователь открывает страницу `/products/:id` и запрос к API находится в процессе выполнения
- **THEN** система отображает skeleton вместо содержимого карточки

### Requirement: Карточка отображает данные товара

Система MUST при успешном ответе 200 отображать данные `internal_product.FullResponse` и MUST использовать только поля этого контракта: название, категорию, цену, остаток, дату последнего обновления и поставщика с телефоном и адресом.

#### Scenario: Поля карточки отображены

- **WHEN** GET-запрос на `/api/v1/products/{id}` возвращает 200 с телом `internal_product.FullResponse`
- **THEN** система отображает название `name`, категорию `category.name`, цену `price` без изменений, остаток `available_stock`, дату последнего обновления `last_update_date`
- **THEN** система отображает блок поставщика: имя `supplier.name`, телефон `supplier.phone_number`, адрес `supplier.address.country`, `supplier.address.city`, `supplier.address.street`

### Requirement: Фотография товара отображается на карточке

Система MUST отображать фотографию товара, загружая её через существующую операцию `GET /api/v1/products/{id}/image`, и MUST предоставлять действие управления фотографией, открывающее существующий диалог фотографии этого товара.

#### Scenario: Фотография отображается

- **WHEN** карточка открыта и GET-запрос на `/api/v1/products/{id}/image` возвращает 200 с телом изображения
- **THEN** система отображает фотографию с локализованным доступным именем, описывающим товар

#### Scenario: Фотография отсутствует

- **WHEN** карточка открыта и GET-запрос на `/api/v1/products/{id}/image` возвращает 404
- **THEN** система отображает заглушку отсутствия фотографии без сообщения об ошибке

#### Scenario: Ошибка загрузки фотографии

- **WHEN** карточка открыта и GET-запрос на `/api/v1/products/{id}/image` возвращает 400, 500, 503 или не возвращает ответ
- **THEN** система отображает в области фотографии сообщение из поля `message` ответа, а при его отсутствии — локализованное сообщение об ошибке
- **THEN** состояние отсутствия фотографии не отображается, а карточка не переходит в состояние ошибки: поля, действия и сообщение карточки остаются отображёнными

#### Scenario: Действие управления фотографией

- **WHEN** пользователь активирует действие управления фотографией на карточке
- **THEN** система открывает диалог фотографии этого товара с доступными в нём операциями загрузки, замены и удаления по правилам существующей capability фотографий

### Requirement: Отсутствующий товар обрабатывается состоянием карточки

Система MUST при ответе 404 на `GET /api/v1/products/{id}` отображать состояние отсутствия товара с локализованным сообщением и действием возврата к списку товаров.

#### Scenario: Товар не найден

- **WHEN** GET-запрос на `/api/v1/products/{id}` возвращает 404
- **THEN** система отображает локализованное сообщение об отсутствии товара
- **THEN** система отображает действие возврата к списку товаров
- **THEN** содержимое карточки не отображается

### Requirement: Ошибки загрузки карточки отображаются с повтором

Система MUST при неуспешных ответах 400, 500, 503 и при сетевой ошибке запроса `GET /api/v1/products/{id}` отображать сообщение об ошибке и действие «Повторить», повторяющее запрос.

#### Scenario: Ошибка с сообщением сервера

- **WHEN** GET-запрос на `/api/v1/products/{id}` возвращает 400 или 500 с полем `message` ErrorResponse
- **THEN** система отображает Alert с сообщением из поля `message`
- **THEN** система отображает в этом Alert действие «Повторить»

#### Scenario: Ошибка без сообщения сервера

- **WHEN** GET-запрос на `/api/v1/products/{id}` возвращает 500 без поля `message`, возвращает 503 независимо от тела ответа, либо запрос не возвращает ответ
- **THEN** система отображает Alert с локализованным сообщением об ошибке
- **THEN** действие «Повторить» отправляет повторный GET-запрос на `/api/v1/products/{id}`

#### Scenario: Повторная загрузка успешна

- **WHEN** повторный GET-запрос на `/api/v1/products/{id}` возвращает 200
- **THEN** система отображает карточку товара
- **THEN** действие «Повторить» не отображается

### Requirement: Ошибка 401 завершает сессию

Система MUST обрабатывать ответ 401 от `GET /api/v1/products/{id}` как истёкший или невалидный токен через общее поведение завершения сессии панели.

#### Scenario: Unauthorized response

- **WHEN** GET-запрос на `/api/v1/products/{id}` возвращает 401
- **THEN** система удаляет токен из localStorage
- **THEN** система очищает кеш TanStack Query и перенаправляет пользователя на `/auth/login`

### Requirement: Возврат к списку товаров

Система MUST предоставлять действие возврата к списку товаров на странице `/products/:id`.

#### Scenario: Возврат из карточки

- **WHEN** пользователь активирует действие возврата на странице `/products/:id`
- **THEN** система открывает страницу `/products`

### Requirement: Данные карточки кешируются

Система MUST кешировать данные карточки в TanStack Query с глобальными правилами панели: повторное открытие карточки того же товара в пределах staleTime (5 минут) не отправляет новый запрос, при устаревании кеша происходит его обновление.

#### Scenario: Повторное открытие карточки в пределах staleTime

- **WHEN** пользователь повторно открывает карточку того же товара в течение 5 минут
- **THEN** новый GET-запрос на `/api/v1/products/{id}` не отправляется
- **THEN** отображаются данные из кеша

#### Scenario: Повторное открытие карточки после staleTime

- **WHEN** пользователь повторно открывает карточку того же товара позже чем через 5 минут
- **THEN** система отправляет повторный GET-запрос на `/api/v1/products/{id}`

### Requirement: Мутации товара из списка актуализируют карточку

Система MUST актуализировать кеш карточки после успешных мутаций этого товара, выполняемых из списка: после уменьшения остатка карточка при следующем открытии показывает актуальный остаток, после удаления товара — состояние отсутствия товара. Изменения фотографии актуализируют область фотографии через существующую инвалидацию кеша фотографии.

#### Scenario: Остаток уменьшен из списка

- **WHEN** пользователь уменьшил остаток товара из строки списка, затем открыл карточку этого товара
- **THEN** карточка отправляет GET-запрос на `/api/v1/products/{id}` заново и отображает актуальный `available_stock`

#### Scenario: Товар удалён из списка

- **WHEN** пользователь удалил товар из строки списка, затем открыл карточку этого товара по прямой ссылке
- **THEN** GET-запрос на `/api/v1/products/{id}` возвращает 404 и карточка отображает состояние отсутствия товара

#### Scenario: Фотография изменена через диалог

- **WHEN** пользователь загрузил, заменил или удалил фотографию товара через диалог на карточке
- **THEN** область фотографии карточки показывает актуальное состояние фотографии

### Requirement: Локализация карточки

Система MUST отображать все тексты карточки (названия полей, действия, состояния, сообщения) на выбранном языке: английском или русском.

#### Scenario: Английский язык

- **WHEN** пользователь открывает карточку товара при выбранном английском языке
- **THEN** все тексты карточки отображаются на английском

#### Scenario: Русский язык

- **WHEN** пользователь открывает карточку товара при выбранном русском языке
- **THEN** все тексты карточки отображаются на русском

### Requirement: На карточке нет операций, не поддерживаемых контрактом

Система MUST отображать на карточке только просмотр данных, управление фотографией и возврат к списку и MUST NOT отображать операции изменения полей товара или увеличения остатка, поскольку контракт API их не предоставляет.

#### Scenario: Состав действий карточки

- **WHEN** карточка товара открыта
- **THEN** на карточке доступны только действие управления фотографией и действие возврата к списку
- **THEN** на карточке нет действий редактирования полей товара, изменения цены и увеличения остатка
