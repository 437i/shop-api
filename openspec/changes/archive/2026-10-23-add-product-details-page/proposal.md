# Proposal

## Why

Раздел «Товары» показывает только строку списка: название, категорию, цену и остаток. Данные, которые backend отдаёт по карточке товара — поставщика с телефоном и адресом, категорию с идентификатором, дату последнего обновления (`internal_product.FullResponse`, `GET /api/v1/products/{id}`), — в панели недоступны, потому что этот эндпоинт фронтендом не используется. Отдельная страница карточки также станет естественным местом для последующих операций товара, которых сейчас в панели нет вовсе.

## What Changes

- Новая защищённая страница `/products/:id` — карточка товара: получает данные через `GET /api/v1/products/{id}` и отображает все поля `internal_product.FullResponse` (name, category, price, available_stock, last_update_date, supplier с телефоном и адресом).
- Карточка отображает фотографию товара через существующий модуль `product-images` (`GET /api/v1/products/{id}/image`) и предоставляет действие управления фотографией, открывающее существующий диалог `ProductImageDialog` — новая логика загрузки, замены и удаления не пишется.
- Переход из списка: в меню действий каждой строки `/products` появляется действие карточки товара, открывающее страницу `/products/{id}`; возврат к списку — действие на самой странице.
- Состояния страницы: skeleton загрузки, карточка при 200, отсутствие товара при 404 (сообщение и возврат к списку), ошибки 400/500/503 и сетевая ошибка с действием «Повторить», завершение сессии при 401 через существующий глобальный обработчик.
- Кеширование данных карточки в TanStack Query по правилам панели (staleTime 5 минут, автообновление по фокусу при устаревании).
- Ключи локализации EN/RU для всех текстов карточки.
- **Без изменений Go API, Java-сервиса и схемы БД.** Контракт используется ровно в том виде, в каком он объявлен в `api/docs/swagger.yaml`.
- **Не является BREAKING**: существующие страницы не меняют поведение, в `/products` добавляется только пункт меню.

Не входит в scope:
- Редактирование полей товара, пополнение остатка и любые другие операции записи по карточке — их нет в API (`PATCH /api/v1/products/{id}` и операция увеличения остатка отсутствуют), панель не добавляет действия, которые контракт не поддерживает.
- Достижимость товара с нулевым остатком из списка: `GET /api/v1/products` возвращает только товары с `available_stock > 0`, поэтому переход из списка возможен только для товаров в наличии; карточка по прямому URL корректно открывает и товар с нулевым остатком (`GET /api/v1/products/{id}` не фильтрует по остатку), но отдельного способа найти такой товар в панельных списках это изменение не создаёт.
- Справочник категорий, справочник адресов, поиск, пагинация, страница поставщика `/suppliers/:id`.
- Живой e2e-сценарий для карточки (`frontend/e2e-live/`) — существующая пятисценарная живая процедура остаётся без изменений.

## Capabilities

### New Capabilities

- `frontend/product-details`: страница карточки товара — загрузка данных через `GET /api/v1/products/{id}`, отображение полей `FullResponse`, фотографии и действия управления фотографией, состояния загрузки, отсутствия товара, ошибок и завершения сессии, возврат к списку, локализация.

### Modified Capabilities

- `frontend/products-list`: в меню действий строки товара добавляется действие открывания карточки `/products/:id`. Требования таблицы, состояний, кеширования и локализации списка не меняются.

## Impact

**Используемые API-эндпоинты** (контракт не меняется, перечислены как затрагиваемая поверхность):
- `GET /api/v1/products/{id}` — 200 `internal_product.FullResponse`; 400 `invalid product id` (некорректный UUID в пути); 401 unauthorized; 404 `product not found`; 500. Код 503 в swagger не задокументирован — это поведение auth middleware, общее для всех защищённых эндпоинтов панели (так же задокументировано в спецификации `frontend/products-list`).
- `GET /api/v1/products/{id}/image` — 200 `application/octet-stream`; 404 `image not found`; 400 `invalid product id`; 500/503; используется существующим модулем `product-images`.
- `POST /api/v1/products/{id}/image`, `PUT /api/v1/images/{id}`, `DELETE /api/v1/images/{id}` — через существующий диалог без изменений поведения.
- `GET /api/v1/products` — существующий список; после загрузки фотографии его `image_id` заполняется, что делает действие замены/удаления доступным и на карточке.

**Код фронтенда:**
- `frontend/src/app/router.tsx` — новый защищённый маршрут `/products/:id`.
- `frontend/src/pages/products/` — страница карточки `ProductDetailsPage.tsx` и хук данных `useProductDetails.ts`.
- `frontend/src/pages/products/ProductsListPage.tsx` — пункт меню действий строки.
- `frontend/src/features/product-images/` — переиспользование запроса фотографии и диалога; при выделении общий компонент отображения изображения, применяемый и диалогом, и карточкой.
- `frontend/src/shared/i18n/locales/en/common.json`, `frontend/src/shared/i18n/locales/ru/common.json` — ключи локализации.
- `frontend/src/test/`, `frontend/e2e/` — юнит- и браузерные тесты.

**Зависимости:** новых нет — используются уже подключённые React Router, TanStack Query, react-i18next и компоненты shadcn/ui.

**Не затрагивается:** Go API, Java auth service, схема БД, разделы клиентов и поставщиков, навигация sidebar, живой e2e-набор, архив завершённых изменений.

**Незавершённые вопросы контракта и аутентификации:**
- Профиль пользователя из `FullResponse` не создаётся: `supplier` в ответе — данные поставщика товара, а не сведения о пользователе; панель по-прежнему не запрашивает профиль и права (см. `frontend/admin-access-model`).
- `GET /api/v1/products/{id}` допускает 400 (`invalid product id`), поэтому в отличие от списка товаров карточка должна обрабатывать 400 как ошибку загрузки с сообщением сервера.
- Токен не обновляется при открытии карточки, refresh-механизма в контракте нет: поведение завершения сессии при 401 остаётся тем же, что и у остальных защищённых запросов.
