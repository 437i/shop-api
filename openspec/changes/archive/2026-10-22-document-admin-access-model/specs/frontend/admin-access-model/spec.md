# Spec Delta

## Purpose

Фактическое поведение frontend: панель не применяет ролевых проверок при определении набора отображаемых разделов и действий и не определяет самостоятельно валидность сохранённого токена. Правило открытия защищённых разделов по наличию сохранённого токена принадлежит capability `frontend/protected-navigation` и здесь не дублируется. Capability описывает только поведение интерфейса: серверная проверка токена и отсутствие серверного разграничения прав — отдельные факты, которые эта capability не изменяет и которые остаются вне её предметной области. Отсутствие серверного разграничения прав остаётся зафиксированным риском текущего локального учебного стенда, а не постоянной целевой моделью безопасности.

## ADDED Requirements

### Requirement: Панель не применяет ролевых проверок

Панель MUST NOT проверять роль или иные атрибуты доступа при определении набора отображаемых разделов и действий. Правило открытия защищённых разделов по наличию сохранённого в localStorage токена остаётся в capability `frontend/protected-navigation` и в этой capability не дублируется.

#### Scenario: Роль пользователя не влияет на набор разделов и действий

- **WHEN** два пользователя с сохранёнными токенами открывают один и тот же раздел
- **THEN** панель отображает обоим одинаковый набор разделов и действий

### Requirement: Панель не определяет валидность токена самостоятельно

Панель MUST NOT определять самостоятельно валидность сохранённого токена — подлинность и срок действия определяет сервер. Capability не определяет и не гарантирует разрешения на стороне Go API или Java-сервиса аутентификации.

#### Scenario: Валидность токена определяет сервер, а не панель

- **WHEN** в localStorage присутствует непрозрачный токен, который сервер считает недействительным
- **THEN** панель открывает раздел по факту наличия сохранённого токена, не анализируя его
- **THEN** отказ определяется ответом сервера и обрабатывается в соответствии с `frontend/protected-navigation`

### Requirement: Панель не запрашивает сведения о роле и правах

Панель MUST NOT запрашивать у API сведения о роле, правах или профиле пользователя и MUST NOT включать их в запросы: набор отображаемых разделов и действий не вычисляется по таким сведениям.

#### Scenario: Запросы панели не содержат сведений о правах

- **WHEN** панель загружает данные защищённого раздела
- **THEN** запросы к API содержат заголовок `Authorization: Bearer <token>` и не содержат параметров роли, прав или профиля пользователя

#### Scenario: Профиль пользователя не запрашивается

- **WHEN** пользователь работает в административной панели
- **THEN** панель не выполняет запрос профиля текущего пользователя
- **THEN** панель не определяет набор отображаемых разделов и действий по ответу API о пользователе
