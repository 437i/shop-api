# Proposal

## Why

Раздел Products в административной панели отключён, хотя Go API уже поддерживает `GET /api/v1/products`. Администратор не может увидеть каталог товаров, которые доступны в магазине, а без списка товаров невозможно дальнейшее развитие раздела (создание, изображения, остатки). Это первый шаг к управлению каталогом: дешёвое read-only представление существующего контракта.

## What Changes

- Новая защищённая страница `/products` со списком товаров из `GET /api/v1/products`: таблица с колонками Name, Category, Price, Available Stock (поля `name`, `category.name`, `price`, `available_stock` из `internal_product.ListResponse`).
- Состояния страницы по существующим паттернам: skeleton загрузки (5 строк), empty state, Alert при ошибках, успешная таблица, глобальная обработка 401 (очистка сессии, кеша и перенаправление на `/auth/login`).
- Пустой список описывается как отсутствие товаров в наличии: контракт возвращает только товары с `available_stock > 0`, и UI не представляет список как полный реестр товаров.
- Активация пункта меню Products в sidebar и добавление защищённого маршрута `/products`; пункт Suppliers и остальные разделы продолжают работать как раньше.
- Ключи локализации EN/RU для всех новых текстов.
- Unit-тесты (Vitest + Testing Library) и E2E-тесты (Playwright, `page.route()`).

Вне scope (не входит):
- Создание, удаление, редактирование товаров и изменение остатка.
- Загрузка, замена, удаление и отображение изображений товаров.
- Отдельная страница подробностей `/products/:id` и запрос `GET /products/{id}`.
- Фильтры, поиск, сортировка и пагинация (их нет в контракте списка).
- Любые изменения Go API, DTO, БД, миграций или API-контракта; новые зависимости.

## Capabilities

### New Capabilities

- `frontend/products-list`: отображение каталога доступных товаров административной панели через `GET /api/v1/products` с обработкой всех состояний загрузки, ошибок, пустого списка и локализацией EN/RU.

### Modified Capabilities

- `frontend/protected-navigation`: требование «Административный layout содержит навигацию» — пункт «Products» становится активным и открывает `/products`; сценарий «Неактивные разделы недоступны» сохраняет заголовок (правила OpenSpec для MODIFIED не допускают удаление сценариев) и обновляется до состояния «неактивных разделов нет», добавляется сценарий «Переход в раздел товаров». Остальные требования и сценарии не меняются.

## Impact

**Затронутый код:**
- `frontend/src/pages/products/` — новая `ProductsListPage.tsx` (каталог `pages/products/` уже существует как пустая заготовка).
- `frontend/src/app/router.tsx` — защищённый маршрут `/products` внутри существующего layout.
- `frontend/src/app/AdminLayout.tsx` — активация пункта Products, определение активного пункта по текущему маршруту.
- `frontend/src/shared/i18n/locales/en/common.json`, `frontend/src/shared/i18n/locales/ru/common.json` — новые ключи раздела `products`.
- `frontend/src/test/` — unit-тесты страницы; `frontend/e2e/` — расширение `helpers.ts` (мок `GET /api/v1/products`) и новый spec.

**API endpoints:**
- `GET /api/v1/products` → 200 массив `internal_product.ListResponse` (`id`, `name`, `category` с `id` и `name`, `price` (строка), `available_stock` (число), `image_id`), требует Bearer-авторизацию; 500 (handler, сообщение `internal server error`); 401 и 503 от auth middleware (тела с полем `error`, без `message`).
- `GET /api/v1/products` возвращает **только товары с `available_stock > 0`** (`api/internal/product/pg_repository.go`, `Where(available_stock > 0)`), без пагинации, фильтров и сортировки по контракту (`swagger.yaml`).
- `GET /products/{id}`, `POST /products`, `DELETE /products/{id}`, `PATCH /products/{id}/stock`, `/products/{id}/image` и `/images/{id}` не вызываются из frontend-кода в этом изменении; `POST /products`, `PATCH /products/{id}/stock` и `DELETE /products/{id}` используются только вручную для подготовки и очистки данных в рамках ручной проверки 5.3.

**Ограничения контракта:**
- `price` — строка без валюты; выводится как есть, без вычислений и форматирования, не описанного в контракте.
- `category` — вложенный объект (`category.name`); поля могут отсутствовать по схеме, поэтому отображаются безопасные пустые значения, как в существующих таблицах.
- `image_id` присутствует в списке, но отображение изображений вне scope — thumbnail не добавляется.
- `400` для `GET /products` не предусмотрен контрактом: у запроса нет query-параметров, а handler возвращает 400 только при ошибке привязки параметров. Обрабатываются применимые ответы: 500, 503, сетевая ошибка и 401; прочие не-401 ошибки показываются общим серверным сообщением.
- Явной кнопки повторной загрузки в существующей архитектуре нет: восстановление после ошибки происходит по общим правилам TanStack Query (повторный фокус вкладки, повторное открытие страницы), новое поведение не вводится.

**Зависимости:**
- Только существующие пакеты, UI-компоненты (table, skeleton, alert), API-клиент и i18next; новых зависимостей нет.
- Типы `internal_product.ListResponse` уже сгенерированы в `frontend/src/shared/api/generated/schema.d.ts` — регенерация не требуется, контракт не меняется.
- Go API, БД и миграции не изменяются.

**Системы:**
- Go HTTP API — источник истины для полей, статусов и семантики «только товары в наличии».
- Локальная проверка — против существующего стека с dev-mock auth-модулем Go API (реальная аутентификация недоступна до подключения Java auth service; ограничение уже задокументировано в `frontend/README.md`). E2E-тесты с `page.route()` не доказывают работу реального API — требуется отдельная ручная проверка.


> **Уточнение (2026-10-21).** Описанное выше — состояние на момент архивации: стенд использовал dev-mock auth, реальная аутентификация была недоступна. С тех пор `docker-compose` поднимает Java auth service (`auth`, `auth-postgres`), `cmd/api` запускает `app.Module` с реальным gRPC-клиентом, а dev-mock приведён в соответствие и остаётся опциональной альтернативой; поэтому приведённые выше утверждения о недоступности реального auth service, об актуальности `frontend/README.md` и о работе раздела только при dev-mock auth не описывают текущий стенд — см. `frontend/README.md`, раздел «Local authentication».

**Незавершённые вопросы:**
- Нет блокирующих. Принятые решения: (1) колонки ограничены данными `ListResponse` — Name, Category, Price, Available Stock, без Last Update Date (его нет в списке) и без изображения; (2) empty state формулируется как «нет товаров в наличии», чтобы не заявлять полноту каталога; (3) детальная страница товара и запрос `GET /products/{id}` отложены до следующих изменений.
