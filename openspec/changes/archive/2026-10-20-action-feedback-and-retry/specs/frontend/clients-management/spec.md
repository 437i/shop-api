# Spec Delta

## ADDED Requirements

### Requirement: Успешные операции с клиентом подтверждаются уведомлением

Система MUST отображать уведомление об успехе после успешного ответа сервера на создание, удаление или изменение адреса клиента.

#### Scenario: Клиент создан
- **WHEN** POST-запрос на `/api/v1/clients` вернул 201
- **THEN** система отображает уведомление об успешном создании клиента

#### Scenario: Клиент удалён
- **WHEN** DELETE-запрос на `/api/v1/clients/{id}` вернул 204
- **THEN** система отображает уведомление об успешном удалении клиента

#### Scenario: Адрес клиента изменён
- **WHEN** PATCH-запрос на `/api/v1/clients/{id}/address` вернул 204
- **THEN** система отображает уведомление об успешном изменении адреса клиента

## MODIFIED Requirements

### Requirement: Существующее поведение списка сохраняется

Система MUST сохранять текущее поведение страницы клиентов: состав колонок, skeleton при загрузке, empty state, отображение ошибок и кеширование списка; состояние ошибки списка при этом дополняется действием повторной загрузки согласно `frontend/clients-list`.

#### Scenario: Состав списка не меняется

- **WHEN** список клиентов успешно загружен
- **THEN** таблица отображает колонки Name, Surname, Birthday, Gender, Registration Date без изменений
- **THEN** действия создания, удаления и изменения адреса доступны, но не изменяют состав колонок

#### Scenario: Состояния загрузки, пустого списка и ошибок

- **WHEN** список находится в процессе загрузки
- **THEN** система отображает skeleton загрузки, как раньше
- **WHEN** сервер возвращает пустой массив
- **THEN** система отображает "No clients found", как раньше
- **WHEN** запрос списка завершается ошибкой
- **THEN** система отображает Alert с сообщением об ошибке, как раньше
- **THEN** этот Alert содержит действие «Повторить», как описано в `frontend/clients-list`
